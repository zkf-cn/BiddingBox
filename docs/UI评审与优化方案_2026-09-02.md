# 招标百宝箱 · UI 设计评审与优化方案

> 评审范围：`src/` 全量 13 个页面/组件 + 2 个样式文件（4329 行）
> 评审日期：2026-09-02
> 方法：设计令牌交叉核对（脚本扫描 `var(--x)` 定义 vs 引用）、组件一致性比对、可访问性检查、深浅双主题走查

---

## 一、总体评价

**结论：底层设计系统健康度不错，问题集中在"两套 UI 语言并存"和"移植代码未收敛"。**

| 维度 | 评分 | 说明 |
|------|------|------|
| 设计令牌体系 | ★★★★☆ | `theme.css` 变量覆盖完整、命名清晰，深浅双主题对称性好 |
| 组件一致性 | ★★☆☆☆ | 存在 **2 套卡片头 / 2 套表格 / 3 套圆角 / 3 套 tooltip 实现** |
| 深浅主题适配 | ★★★☆☆ | 主体适配到位，但 QuotaView 有 4 处硬编码色在深色下失读（已修） |
| 响应式 | ★★★★☆ | 三档断点（1024/900/640）覆盖合理，QuotaView 移动端有独立方案 |
| 可访问性 | ★★★☆☆ | 有 focus-visible + aria-label，但触控目标偏小、小字号对比度偏低 |
| 信息架构 | ★★★☆☆ | 首页 6 个 section 权重平均；侧边栏 9 项平铺，扫读困难 |

**最突出的问题**：`QuotaView` 是从参考网页"完全照搬"移植进来的，它自带一套 `--c-*` 别名变量、8px 圆角、8px 间距节奏，与站内 `base.css` 的 14px 圆角、24px 节奏并存——两个页面并排看会像两个产品。

## 二、已修复的缺陷（P0，本轮直接落地）

### 1. CalcView 引用了 6 个**不存在**的 CSS 变量 🔴

脚本扫描发现（`--x/--y/--r` 为 JS 动态注入，属正常）：

| 引用的变量 | 实际应引用 | 影响位置 | 实际渲染后果 |
|-----------|-----------|---------|-------------|
| `--c-bg-soft` | `--bg-subtle` | `.stats-sum td` 背景 | 费用统计行**无底色**，看不出是合计行 |
| `--c-border` | `--border-strong` | `.stats-sum td` 上边框 | 分隔线消失 |
| `--c-text` | `--text` | 合计行文字 | 回退继承色（浅色下恰好正确，深色下错误） |
| `--c-brand` | `--brand-strong` | 合计金额 | 同上 |
| `--c-text-muted` | `--text-muted` | 条数说明、固定单价标题 | 小字未降级为灰色，与正文同级 |
| `--c-brand-50` | `--brand-soft` | `.fixed-box` 渐变 | **整条 gradient 声明失效** → 固定单价模式结果框完全透明 |

> **这是本轮最严重的发现**：CSS 引用未定义变量**不报错、构建通过、只在浏览器运行时静默失效**。
> 建议把变量核对脚本固化进 CI（见第五节 F1）。

### 2. QuotaView 深色模式下失读的硬编码色 🔴

| 位置 | 原值 | 深色模式后果 | 修复 |
|------|------|------------|------|
| `.qt mark` | `background:#ffe28a`，色继承 | 亮黄底 + 浅色字（`#e5edf7`）→ **完全不可读** | 新增 `--mark-bg` / `--mark-text` 双主题变量 |
| `tr.qt-note td` | `#fffbe6 / #7a5d00 / #e6d790` | 亮黄块刺眼 | 改 `--warn-soft` / `--warn` / `--border-strong` |
| `.addbtn.added` | `#ccc / #bbb / #fff` | 亮灰块 + 白字 | 改 `--bg-sunken` / `--border-strong` / `--text-muted` |
| `.note-doc table td` | `border:1px solid #444` | 深色下边框比背景还深，表格线消失 | 改 `--border-strong` |

### 3. 首页 Hero 无限动画未尊重系统设置 🟡

`animation: heroGradientMove 8s infinite` 常驻运行，页面挂一天就跑一天。已补充 `prefers-reduced-motion` 降级。

## 三、待决策的优化方案（按优先级）

### P1 · 高优先级

#### S1. 统一圆角体系：从 3 套收敛为 1 套

| 当前 | 值 | 使用范围 |
|------|-----|---------|
| 全局（base.css） | 14 / 10 / 18px | 卡片、按钮、输入框、Modal 外的全部页面 |
| QuotaView | 8 / 6 / 4px | 面板、表格、标签、按钮 |
| Modal | 10px | QuotaView 说明弹窗 |

**方案 A（推荐）**：QuotaView 接入全局 `--radius`，面板改 14px、内部元素改 10px。改动约 20 处，视觉上四象限会"松"一点，但全站统一。
**方案 B**：保留 QuotaView 的紧凑圆角（它确实是信息密度最高的页面），但需在 `theme.css` 显式声明 `--radius-compact: 8px` 作为**有意为之的第二个令牌**，而不是散落的裸值。

> 我倾向 **方案 B + 局部收敛**：密度型页面（工期定额、专家分类表格）用 compact，表单/卡片类页面用标准。关键是要有令牌、有注释，而不是随机的 6px/8px/10px。

#### S2. 合并重复组件：`.card-head` vs `.panel-hd`

两者是**同一套视觉**（左蓝渐变竖条 + 14px 标题 + 右侧操作区 + 下边框），却各自实现了一遍：

```css
/* base.css */
.card-title::before { width:3px; height:15px; background: var(--brand-gradient); }
/* QuotaView.vue */
.panel-hd .panel-title::before { width:3px; height:15px; background: var(--brand-gradient); }
```

**方案**：删除 `.panel-hd`，QuotaView 改用 `.card-head` / `.card-title`，仅保留 `position:relative`（折叠按钮定位需要）。约 15 行重复代码消失，且以后调竖条样式只改一处。

#### S3. 统计列表缺少"导出 Excel" 🔴 功能缺口

现状：能加入、能清空、刚加了合计行，**但收集的数据只能看不能带走**。用户手动攒了 20 条测算结果，却只能手抄或截图。

**方案**：在「统计列表」卡头加一个 `导出 Excel` 按钮，复用已有的 `exportWorkbook`，输出列：计算器 / 参数 / 基准价 / 下浮后 / 费率依据文号，末行附「费用统计」合计。这是投入产出比最高的一项。

#### S4. 侧边栏 9 项平铺，扫读困难

现状：9 个计算器同一图标、同一层级、等长排列，且分组标题「计费计算器」下只有一个组——等于没有分组。

**方案 A（推荐）**：恢复语义分组（招标代理 / 造价咨询 / 工程交易…），用 `sidebar-divider` 分隔，每组 2-4 项。
**方案 B**：保持平铺，但给每个计算器配**不同图标**（现在 9 个全用 calculator），并在收起态依赖 tooltip 区分。
**方案 C**：平铺 + 顶部加一个搜索框，输入即过滤。

> 你之前明确要求"不要细分分组，全部为 1 个分组"，所以**默认按方案 B**（换图标 + 保留单分组），需要时再切 A。

#### S5. tooltip 机制收敛：3 套实现 → 1 套

现状：
1. `[data-tooltip]::after` 伪元素（全局，会被 `overflow:hidden` 裁剪）
2. `.sidebar-tip` JS fixed 浮动层（侧边栏，绕开裁剪）
3. `.toggle-tip` JS fixed 浮动层（QuotaView 折叠按钮，绕开裁剪）

后两套都是**为绕开第 1 套的裁剪缺陷**打的补丁。

**方案**：删掉 CSS 伪元素方案，统一为一个 `<TooltipLayer>` 组件 + `v-tooltip` 指令，`position:fixed` + 边界翻转（右/上空间不足时自动换边）。一次性消除所有"被遮挡/位置不对/不消失"类问题——这几类问题在本项目里已经反复出现过 8+ 轮。

### P2 · 中优先级

#### S6. 首页信息层级过重

现状 6 个 section 纵向堆叠：Hero → 9 张计费卡 → 2 张查询卡 → 网站用途 → 数据版本表 → 免责声明。后两块是**低频合规信息**，却与功能入口同等权重。

**方案**：把「网站用途」「数据版本声明」「风险与免责」折叠进一个 `<details>` 手风琴，默认收起，标题行显示"数据版本 · 免责声明 · 使用说明"。首屏只留 Hero + 功能入口，纵向长度减少约 45%。

#### S7. 触控目标偏小

| 元素 | 当前 | 移动端推荐 |
|------|------|-----------|
| `.btn-sm` | 30px 高 | ≥36px |
| `.addbtn`（工期定额加号） | 26×22px | ≥44×44px（QuotaView 移动端已放大到 32×28，仍偏小） |
| `.st-del`（统计列表删除 ×） | 无尺寸，纯文本 | ≥44×44px |
| `.pager` 翻页按钮 | 30px | ≥40px |

**方案**：在 `@media (max-width:640px)` 内统一放大，或用 `::after` 撑开点击热区（`padding` 不变、热区变大）。

#### S8. 小字号对比度

现状最小字号 11px（`.hint`、`.st-hint`、`.hero-stat-label`、`.group-title .crumb`），色值 `--text-muted`。

| 组合 | 对比度 | WCAG AA（<18pt 需 4.5:1） |
|------|--------|--------------------------|
| `#6b7280` on `#ffffff` | 4.83:1 | ✅ 通过 |
| `#8b9ab0` on `#151f31` | 5.62:1 | ✅ 通过 |

对比度本身达标，**但 11px 中文的可读性仍偏低**。建议全局最小字号提到 12px，11px 仅用于角标/徽章。

#### S9. 主按钮在深色模式下对比度偏低

`.btn-primary` 深色态：`linear-gradient(#3b7ef5 → #2563eb)` + 白字，白字在 `#3b7ef5` 上约 **3.3:1**，低于 4.5:1。

**方案**：深色下改为 `linear-gradient(#2563eb → #1d4ed8)`（更深的底），或保留渐变但文字改用 `#fff` + `font-weight:600` + 轻微文字阴影。

#### S10. Hero 渐变在深色模式下未适配

现状：深浅主题都是 `linear-gradient(#2563eb → #1d4ed8 → #3b82f6 → #1e40af)`，深色页面里是一整块高亮蓝，与 `#0b1220` 背景对比过冲。

**方案**：深色下换 `linear-gradient(135deg, #1e3a8a, #172554)`（深海军蓝），保持品牌感但压低亮度。

## 五、工程化建议

### F1. 把 CSS 变量核对脚本固化进构建前检查

这次 P0 缺陷能被发现，靠的是一次性脚本。**建议固化为 `scripts/check-css-vars.mjs`**，在 `npm run build` 前执行：

```js
// 扫描 src/**/*.{vue,css}：
// 1. 收集所有 `--x:` 定义
// 2. 收集所有 `var(--x)` 引用
// 3. 差集（排除 JS 动态注入的白名单 --x/--y/--r）非空 → exit 1
```

同类教训已第二次出现（第一次是批量替换硬编码色时只改引用方漏改定义方，构建同样通过）。**CSS 变量未定义是合法语法，编译器不会报错**——必须有主动检查。

### F2. 建立最小设计令牌文档

把 `theme.css` 的变量分组（颜色 / 圆角 / 阴影 / 间距 / 字号）+ 使用场景写进 `docs/design-tokens.md`，新页面开发时先查令牌再写代码，避免再生 `--c-*` 这类第二套命名。
