工程化建议

防止同类问题复发
F1 · 固化 CSS 变量核对脚本
强烈建议

本次 P0 缺陷靠一次性脚本发现。建议固化为 scripts/check-css-vars.mjs，在 build 前执行。

扫描 src/**/*.{vue,css}
① 收集所有 --x: 定义
② 收集所有 var(--x) 引用
③ 差集非空（排除 --x/--y/--r 白名单）→ exit 1

同类教训已是第二次出现 —— CSS 变量未定义是合法语法，编译器不会报错，必须主动检查。

F2 · 建立设计令牌文档
建议

把 theme.css 的变量按「颜色 / 圆角 / 阴影 / 间距 / 字号」分组，附使用场景，写入 docs/design-tokens.md。

新页面开发流程：先查令牌 → 再写代码。

这是避免再生 --c-* 这类第二套命名的根本手段 —— 本次 6 个错误变量，正是从参考项目移植时沿用了对方的命名前缀。
